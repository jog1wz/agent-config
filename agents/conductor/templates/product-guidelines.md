# Product Guidelines

## Prose Style

All documentation and communication should be **Technical & Direct**.

-   Be clear, concise, and to-the-point.
-   Use active voice.
-   Avoid jargon and ambiguity.

## Branding

This project follows the official **Corporate Branding** guidelines for all public-facing documentation.

## Developer Experience (DX)

The following principles guide the developer experience:

-   **Comprehensive Documentation:** Provide clear and comprehensive documentation for all features.
-   **Responsive Support:** Offer fast and responsive support for developers.

## Contribution Guidelines

All contributions should adhere to the following guidelines:

-   **Commits:** If possible, add the changes in a single commit (mostly using `git commit --amend --no-edit`).
-   **Pull Requests:** Create a detailed Pull Request with the "DP" number in the name that describes the changes.
